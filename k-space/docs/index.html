🔶 MLD - Modèle Logique des Données

Tables Principales

  • users (id_user PK, username, email, password_hash, avatar_url, created_at)
  • genres (id_genre PK, name, description, created_at)
  • dramas (id_drama PK, id_genre FK, title, description, release_year, episode_count, poster_url, created_at)

Tables Associatives

  • user_dramas - Historique de visionnage (N:M entre users et dramas)
  • ratings - Notes des utilisateurs (N:M entre users et dramas)
  • community_members - Membres des communautés (N:M entre users et communities)

Relations

  • dramas.id_genre → genres.id_genre (1:N)
  • messages.id_user → users.id_user (N:1)
  • messages.id_community → communities.id_community (N:1)
  • recommendations.id_user → users.id_user (N:1)
  • recommendations.id_drama → dramas.id_drama (N:1)

🔸 MPD - Modèle Physique des Données

Types PostgreSQL Utilisés

  • UUID - Identifiants uniques universels
  • VARCHAR(n) - Chaînes de caractères limitées
  • TEXT - Texte illimité
  • INTEGER - Nombres entiers
  • TIMESTAMPTZ - Date/heure avec fuseau
  • BOOLEAN - Valeurs true/false

Exemple de Table

CREATE TABLE dramas (
    id_drama UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    id_genre UUID NOT NULL REFERENCES genres(id_genre),
    title VARCHAR(255) NOT NULL,
    description TEXT,
    release_year INTEGER,
    episode_count INTEGER,
    poster_url TEXT,
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_dramas_genre ON dramas(id_genre);

Contraintes de Sécurité

  • PRIMARY KEY sur tous les id_*
  • FOREIGN KEY pour l'intégrité référentielle
  • UNIQUE pour éviter les doublons
  • CHECK pour valider les valeurs (ex: score entre 1-10)
  • NOT NULL sur les champs obligatoires

🏗️ Architecture du Projet (Simplon AI)

BLOC 1 — DATA

Collection, stockage et mise à disposition des données

  • Data Pipeline: Web scraping (MyDramaList, IMDB), APIs externes, fichiers CSV
  • PostgreSQL: Base de données hébergée sur Supabase avec RLS
  • Data API: FastAPI exposant les endpoints REST pour dramas, ratings, historique
  • Technologies: Python, Pandas, BeautifulSoup, PostgreSQL

BLOC 2 — AI

Modèles et services d'intelligence artificielle

  • Algorithme: Collaborative Filtering pour recommandations personnalisées
  • Training: Entraînement sur historique utilisateur et ratings
  • AI API: Endpoint POST /recommend retournant top dramas suggérés
  • Monitoring: Métriques RMSE, précision, satisfaction utilisateur
  • Technologies: Python, Scikit-learn, FastAPI, Joblib

BLOC 3 — APPLICATION

Application web intégrant les services IA

  • Frontend: React + TypeScript + Tailwind CSS
  • Backend: FastAPI orchestrant Data API et AI API
  • Features: Tracking dramas, notation, recommandations IA, communautés, chat
  • CI/CD: GitHub Actions, tests automatisés, déploiement continu
  • Monitoring: Sentry (erreurs), DataDog (performance)

Flux de Données

External APIs → Data Pipeline → PostgreSQL → Data API → Backend → Frontend
                                   ↓
                        ML Training → AI Model → AI API ↗
